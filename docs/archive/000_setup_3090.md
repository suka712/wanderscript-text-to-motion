## 4. Environment
- Use `wander/requirements.txt` — it is pinned to the exact versions proven working on
  the 4090 (conda env `afford`, python 3.8.20) across every verify script in this repo,
  **not** T2M-GPT's own upstream `environment.yml` (torch 1.8.1/cuda10.1), which predates
  and is incompatible with Ampere/Ada-generation cards (3090/4090 are both Ampere/Ada).
  The file has the exact install sequence at the top (torch/torchvision/torchaudio with
  the cu113 index URL, then `pip install -r requirements.txt`).
- cu113 wheels work on newer drivers via CUDA minor-version compatibility, but check the
  3090 box's `nvidia-smi` driver version first if `torch.cuda.is_available()` comes back
  False after install.
- `pytorch3d` is deliberately NOT in requirements.txt — nothing in this repo's pipeline
  needs it (see the comment in requirements.txt for why); skip it unless you specifically
  add SMPL mesh rendering later.
- Verify `import torch; torch.cuda.is_available()` before moving on.

## 5. Smoke test — the gate
- Run `scripts/verify/check14_mpjpe_evaluator_norm.py` on the 3090 (it prints the
  H3D-baseline and per-category HUMANISE MPJPE together, including walk).
- **Pass = it reproduces a known value**: HUMANISE walk ~47.9mm, H3D baseline ~45.3mm.
- **Normalization pitfall — read before running.** The frozen VQ-VAE checkpoint has its
  OWN mean/std at `checkpoints/t2m/VQVAEV3_CB1024_CMT_H1024_NRES3/meta/{mean,std}.npy`,
  which differ from `H3D_ROOT/Mean.npy`/`Std.npy`. Using the wrong one inflates every
  MPJPE number ~2-3x (H3D baseline alone: 137.3mm wrong-norm vs 45.3mm correct) and has
  already cost real time twice in this project being mistaken for a genuine
  data/environment problem. `check14` already uses the correct (checkpoint's own) norm —
  use it as-is rather than writing a new smoke test from scratch. If your number comes
  out ~2-3x high, this is almost certainly the cause, not a real parity failure.
- If the number matches: 3090 is at parity, proceed to `001_grounding_probe.md`.
- If it doesn't (and it's not the normalization pitfall above): environment/data/
  checkpoint mismatch — STOP and diagnose. Do not build the probe on an unverified box.
